Update the existing Order Loop product at `logistics.olyxee.com`.

The goal is to prepare Order Loop for new plans and upcoming features launching on **1 August 2026**, while keeping the current product stable and unchanged for existing users.

Do not redesign or replace the current Order Loop product.

Keep the current:

* Dashboard
* Sidebar structure
* Order creation flow
* Customer management
* Status update flow
* Email notification functionality
* Visual style
* Typography
* Colours
* Responsive behaviour

This release should add announcement UI, pricing visibility, billing foundations, future integration foundations, and disabled feature code.

Nothing unfinished should affect current users.

# 17. Paystack test integration

Paystack test credentials are available.

Do not hardcode the credentials into source files.

Store them only in **Replit Secrets**.

Use these environment-variable names:

```env
PAYSTACK_PUBLIC_KEY=<provided Paystack test public key>
PAYSTACK_SECRET_KEY=<provided Paystack test secret key>
PAYSTACK_MODE=test
APP_URL=https://logistics.olyxee.com
```

The provided test secret key must only be entered into Replit Secrets.

Do not place it in:

* Frontend source code
* GitHub
* Configuration files committed to Git
* API responses
* Console logs
* Screenshots
* Public environment variables

The frontend may access only the Paystack public key.

The backend must access the secret key using:

```ts
const paystackSecretKey = process.env.PAYSTACK_SECRET_KEY;

if (!paystackSecretKey) {
  throw new Error("PAYSTACK_SECRET_KEY is not configured");
}
```

# 19. Billing endpoints

Create these backend endpoints:

```text
POST /api/billing/initialize
GET  /api/billing/verify/:reference
POST /api/webhooks/paystack
GET  /api/billing/subscription
POST /api/billing/cancel
```

## Initialize payment

The backend must:

* Authenticate the current user
* Validate the selected plan
* Use the backend plan price
* Never trust a price sent from the frontend
* Create a unique payment reference
* Initialize the Paystack transaction
* Return only the authorization URL and reference

## Verify payment

The backend must verify the transaction directly with Paystack.

Only after successful verification may the system update:

```ts
plan
subscriptionStatus
billingCustomerCode
billingSubscriptionCode
currentPeriodStart
currentPeriodEnd
```

## Webhook

Use:

```text
https://logistics.olyxee.com/api/webhooks/paystack
```

Verify the Paystack signature using the server-side secret key.

Reject invalid webhook signatures.

Make webhook processing idempotent so the same event cannot activate a subscription twice.

Handle relevant events such as:

```text
charge.success
subscription.create
invoice.create
invoice.payment_failed
subscription.disable
subscription.not_renew
```

Store webhook event IDs or transaction references to prevent duplicate processing.

## Callback

Use:

```text
https://logistics.olyxee.com/billing/callback
```

The callback page must not trust query parameters as proof of payment.

It must ask the backend to verify the payment.

This release is complete when:

* Existing Order Loop functionality still works.
* Current users display the BETA plan.
* No current usage limits are enforced.
* The sidebar announcement is visible.
* What’s New, Coming Soon, and Upgrade Plan pages exist.
* The launch countdown works.
* Free, Pro, and Business plans are visible.
* Existing-user trial dates are configured.
* SMS foundations exist but real SMS is disabled.
* Business branding foundations exist but are disabled.
* Public API foundations exist but are disabled.
* Automated call-centre foundations exist but are disabled.
* Paystack test checkout can be tested safely in development.
* Paystack secrets are stored only in Replit Secrets.
* Billing remains disabled for normal production users.
* Current email notifications remain unchanged.
* No customer, order, or historical data is removed.

This must feel like a controlled preparation release, not a product rebuild.
